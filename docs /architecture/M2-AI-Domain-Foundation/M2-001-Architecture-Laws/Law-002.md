Law-002
Observation Belongs to Resource（Observation 永远属于 Resource）

这是今天新增，也是我认为最重要的一条。

Purpose

Observation 不是 Connector 产生的。

Observation 不是数据库产生的。

Observation 不是 AI 产生的。

Observation 是：

某一个 Resource 在某一个时间点产生的一条不可变事实。

Why

例如：

Redis：

Memory：

8GB

是谁产生的？

不是：

Redis Connector。

真正产生的是：

Redis Resource。

Connector：

只是采集。

因此：

Observation 的真正拥有者：

不是：

Connector。

而是：

Resource
Rule

任何 Observation：

必须：

resourceId != null

禁止：

孤立 Observation。

禁止：

CPU

95%

Redis Cluster

这是一个思想区别。

Observation Characteristics

Observation 必须满足：

Immutable（不可变）
Timestamped（带时间）
Resource Scoped（属于 Resource）
Traceable（可追溯）
Versioned（可扩展）

Observation 永远不会被修改。

只能新增。

Summary

Every Observation Belongs to One Resource.

Three Laws Relationship（三大法则之间的关系）

这三条不是独立的，而是层层递进的：

Law-000
Single Source of Truth
│
▼
定义：每一种事实只能有一个权威来源
│
▼
Law-001
Everything Is Resource
│
▼
定义：企业世界中的所有对象统一抽象为 Resource
│
▼
Law-002
Observation Belongs to Resource
│
▼
定义：所有运行时事实都属于某一个 Resource

因此：

Law-000 回答："什么是真实的事实？"
Law-001 回答："世界里有哪些对象？"
Law-002 回答："对象如何产生运行时事实？"

它们共同构成了整个 AI World Model 的基础。

我建议再补充一条非常重要的约束（以后可以写进 Law-002）

Observation 不是"指标"。

Observation 是事实（Fact）。

举个例子：

传统监控：

CPU = 95%

这是一个指标。

我们的模型：

Observation
----------------------------------
Resource：Order-Service JVM
Type：Metric
Name：system_cpu_load
Value：95%
Timestamp：2026-07-20 10:00:01
Source：JMX

AI 永远分析的是事实集合，而不是单个指标。

这一点会直接影响后面的：

Timeline（事实按时间组织）
Evidence（事实之间建立证据链）
Knowledge（经过验证的事实模式沉淀为知识）

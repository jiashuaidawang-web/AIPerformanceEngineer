## 3. Agent 部署位置

### 3.1 部署方式: systemd Daemon (每台机器一个)

```bash
# 安装路径
/opt/aipe/agent/
├── aipe-agent.jar        # Agent 主程序
├── config.yaml           # 配置文件
├── logs/                 # 日志目录
└── aipe-agent.service    # systemd 服务文件
```

### 3.2 为什么每台都要装?

| 原因 | 说明 |
|------|------|
| **JVM 进程绑定** | Agent 只能采集本机 JVM (通过 PID 附加) |
| **系统指标** | CPU/内存/磁盘/网络是本机的 |
| **高可用** | 某台 Agent 宕机不影响其他机器采集 |
| **横向扩展** | 新增机器只需再装一个 Agent |

### 3.3 资源占用

| 指标 | Agent 占用 |
|------|-----------|
| CPU | < 5% (空闲时 < 1%) |
| 内存 | 128~256MB |
| 网络 | 出站 443, 入站无 |
| 磁盘 | 50MB (安装) + 日志滚动 |

## 5. 详细接入步骤

### 5.1 前置条件

| 要求 | 说明 |
|------|------|
| JDK | 1.8+ (包含 jcmd, jstat, jmap) |
| OS | Linux (CentOS 7+, Ubuntu 20.04+) |
| 权限 | Agent 需要与业务 JVM 同用户 或 root |
| 网络 | 出站 443 到 platform.aipe.io |

### 5.2 一键安装脚本

```bash
#!/bin/bash
# install_aipe_agent.sh — 客户在每台 App Server 执行一次

set -e

AIPE_VERSION="1.0.0"
INSTALL_DIR="/opt/aipe/agent"
PLATFORM_URL="https://platform.aipe.io"
API_KEY="${1:-YOUR_API_KEY}"
CLUSTER_ID="${2:-prod-cluster-01}"

echo "=== AI Performance Agent 安装 ==="
echo "版本: ${AIPE_VERSION}"
echo "平台: ${PLATFORM_URL}"
echo "集群: ${CLUSTER_ID}"

# 1. 创建目录
mkdir -p ${INSTALL_DIR}/{logs,work}

# 2. 下载 Agent
curl -fsSL "${PLATFORM_URL}/download/agent/${AIPE_VERSION}" \
  -o ${INSTALL_DIR}/aipe-agent.jar

# 3. 配置
cat > ${INSTALL_DIR}/config.yaml <<EOF
platform:
  url: ${PLATFORM_URL}
  api_key: ${API_KEY}
  cluster_id: ${CLUSTER_ID}
  
collection:
  interval: 60           # 采集间隔 (秒)
  jvm: true              # JVM 指标
  system: true           # 系统指标
  nginx: true            # Nginx 指标 (如有)
  
logging:
  level: INFO
  file: ${INSTALL_DIR}/logs/agent.log
  max_size: 100MB
  max_files: 5
EOF

# 4. 创建 systemd 服务
cat > /etc/systemd/system/aipe-agent.service <<EOF
[Unit]
Description=AI Performance Engineer Collector Agent
After=network.target

[Service]
Type=simple
User=root
ExecStart=/usr/bin/java -Xmx256m -jar ${INSTALL_DIR}/aipe-agent.jar \
  --config ${INSTALL_DIR}/config.yaml
Restart=always
RestartSec=10
StandardOutput=journal
StandardError=journal

# 资源限制
CPUQuota=10%
MemoryLimit=300M

[Install]
WantedBy=multi-user.target
EOF

# 5. 启动
systemctl daemon-reload
systemctl enable aipe-agent
systemctl start aipe-agent

echo ""
echo "=== 安装完成 ==="
echo "状态: systemctl status aipe-agent"
echo "日志: journalctl -u aipe-agent -f"
echo "验证: curl http://localhost:9090/metrics"
```

### 5.3 客户执行 (每台 App Server)

## 6. Nginx 作为 Resource

Nginx 负载均衡器本身也是监控对象:

### 6.1 自动发现 Nginx

Agent 自动探测本机 Nginx:

```yaml
# config.yaml 自动发现配置
discovery:
  nginx:
    enabled: true
    check_ports: [80, 443, 8080]   # 常见 Nginx 端口
    status_url: "http://localhost/nginx_status"  # 需配置 stub_status
```

### 6.2 Nginx 配置 (客户需加 3 行)

```nginx
# /etc/nginx/conf.d/status.conf
server {
    listen 9091;              # Agent 采集端口
    location /nginx_status {
        stub_status on;       # 开启状态页
        allow 127.0.0.1;      # 只允许本机
        deny all;
    }
}
```

**客户只需要加这 3 行, 不改其他 Nginx 配置。**

### 6.3 Nginx 上报的指标

| 指标 | 说明 |
|------|------|
| active_connections | 当前活跃连接 |
| accepts/handled/requests | 请求计数 |
| reading/writing/waiting | 连接状态分布 |
| upstream_response_time | 上游响应时间 |

## 7. 多实例识别问题

### 7.1 问题

```
Nginx ─▶ App Server 1 (order-svc, PID 12345, 10.0.1.11)
       ─▶ App Server 2 (order-svc, PID 23456, 10.0.1.12)
       ─▶ App Server 3 (order-svc, PID 34567, 10.0.1.13)
```

**从 Platform 看, 3 个 Resource 都叫 `order-svc`, 如何区分?**

### 7.2 解决方案: 多维度标识

```yaml
# Agent 自动生成的 Resource 标识
resource:
  name: "order-svc"
  type: "SERVICE"
  
  # 多维度唯一标识
  instance_id: "order-svc-10.0.1.11"      # 名称-IP
  hostname: "app-server-01"               # 主机名
  private_ip: "10.0.1.11"                 # 内网 IP
  pid: 12345                              # JVM PID
  
  # 标签用于聚合/分组
  tags:
    cluster: "prod-cluster-01"
    env: "production"
    region: "cn-east-1"
    app_version: "1.2.0"
```

```

│   ├── order-svc-10.0.1.12
│   └── order-svc-10.0.1.13
├── nginx-lb (1 instance)
```

## 附录: 传统架构 vs K8s 架构对比

| 维度 | 传统架构 (本文档) | K8s 架构 |
|------|------------------|---------|
| **Agent 部署** | systemd Daemon | DaemonSet / Sidecar |
| **采集方式** | /proc + jcmd | cgroup + API Server |
| **多实例识别** | hostname + IP | Pod Name + Node |
| **Nginx 接入** | stub_status | Service Mesh / Ingress |
| **自动发现** | 端口扫描 + 配置 | K8s API Watch |
| **资源限制** | systemd CPUQuota/MemoryLimit | K8s requests/limits |
| **升级方式** | systemctl restart | Rolling Update |
